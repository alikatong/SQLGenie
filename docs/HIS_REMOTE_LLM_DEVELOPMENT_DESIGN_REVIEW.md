# SQLGenie HIS Schema 远端大模型开发设计二次审查记录

审查日期：2026-07-31
审查对象：`HIS_REMOTE_LLM_DEVELOPMENT_DESIGN.md` v1.0
结论：通过，可进入编码

## 1. 审查边界

本次审查以以下产品边界为前提：SQLGenie 只保存和处理表、字段、注释、关系等 Schema 元数据，以及 HIS 术语、SQL 设计意图和反馈 SQL；系统不包含目标数据库驱动、连接配置、试连、执行计划或 SQL 执行入口。业务数据脱敏不属于该系统。

PDF 不属于本轮交付物，不生成。

## 2. 核查证据

- 对照检查 `backend/main.py`、`backend/llm.py`、`backend/rag.py`、`backend/crud.py`、`backend/database.py`、`backend/schemas.py`、前端工作台与配置页。
- 使用项目实际环境中的 `sqlglot 30.14.0` 解析 MySQL、PostgreSQL 和 Oracle 代表语句。
- 实测普通 JOIN、CTE、派生表、关联子查询的 `qualify` 与 `traverse_scope` 行为。
- 使用仓库示例 Schema 检查关键词分数，并使用当前 `BAAI/bge-small-zh-v1.5` 检查向量相似度与领先幅度。
- 检查设计中每个上线门槛是否有直接测试或可复现证据。
- 对 DOCX 首版执行页设置、标题层级、真实编号、表格 DXA 几何、样式和无障碍结构审计。

## 3. 发现与关闭结果

1. **产品边界残留**：首稿重复讨论真实业务数据和脱敏。已删除该功能线，只保留 Schema 元数据边界和 API Key 非回显。
2. **Oracle 方言被重写**：`sqlglot` 会把 Oracle 输入 `MINUS` 输出为 `EXCEPT`。已规定 AST 仅用于校验，返回原候选 SQL，不使用输出器重写。
3. **外层查询掩盖副作用**：PostgreSQL 数据修改 CTE 的根节点仍是 `Select`。已规定遍历整棵 AST，并拒绝 `Into`、`Lock`、变量赋值、database link 和副作用函数。
4. **列作用域实现风险**：手写别名解析难以覆盖 CTE、派生表和关联子查询。已改为在 AST 副本上使用 `MappingSchema + qualify + traverse_scope`；列类型统一为 `UNKNOWN`，避免厂商自定义类型误报。
5. **向量误召回**：示例“查询 id”对两张无明显目标的表相似度均约 `0.60`。已采用向量绝对阈值 `0.65` 加第一名领先幅度 `0.08`，且保留关键词、显式标识和结构化术语绑定作为主要强证据。
6. **Schema 索引陈旧**：当前实现只比较表名，字段、注释或关系变化可能不刷新。已要求比较完整 `content_hash`、版本化 cosine 集合、按 `db_id` 加锁，并禁止 embedding 期间持有 SQLite 写事务。
7. **自由文本术语证据过强**：首稿允许从 `sql_hint` 推断强证据。已新增 `bindings_json`；只有经过当前 Schema 校验的结构化绑定能成为强证据。
8. **提示词边界不够具体**：已固定 system/user 角色边界、JSON 序列化、字符预算、裁剪顺序和严格模型输出大小；动态文本不能进入 system 消息。
9. **配置密钥契约有回提交风险**：已取消可回填的掩码字符串，GET 只返回配置状态和尾四位；运行时配置与 API 视图使用不同类型。
10. **低证据响应兼容性**：现有 `history_id` 是必填整数。已规定低证据仍写 `NO_SQL` 历史，返回 `model_calls=0`，保持旧字段类型。
11. **追踪生命周期不完整**：已补充 policy 版本、上下文哈希、调用次数、结果、错误码和异常 trace；远端等待期间不得持有 SQLite 事务。
12. **反馈存在绕过路径**：管理员提交可自动批准。已要求管理员自动批准、批准 API 和旧反馈检索共用同一校验入口。
13. **验收证据不完整**：已将门槛重写为 G1-G11，并为每项指定测试文件或可复现检查。

## 4. 接受的剩余风险

- RAG 阈值基于仓库示例和当前 embedding 模型；真实医院 Schema 导入后仍需用固定问句集校准，但不得恢复任意表回退。
- `sqlglot` AST 节点可能跨大版本变化，因此本轮固定 `>=30.14,<31`，升级必须先跑策略回归测试。
- 首次未维护 HIS 术语时仍可依赖 Schema 关键词和向量检索；语义不够明确时返回澄清，不让模型猜测。

## 5. 编码准入结论

设计范围、API 契约、数据模型、失败语义、迁移策略和测试证据已闭合。编码必须按 G1-G11 验收，不得加入目标数据库连接、SQL 执行或业务数据脱敏能力。
